# 高速道路 ライン（下り線・上り線）データ生成ツール

道路名と「下り線の始点のおおよその緯度経度」を指定すると、
OpenStreetMap から高速道路の**下り線と上り線の2本**を取得して、
サイトで使っている `lineData` 形式の JSON を自動生成する Python ツールです。

- 1回のコマンドで **`xxxxx-下り.json` と `xxxxx-上り.json`** の2ファイルを生成します。
- 上下線が分かれている高速道路でも、上下それぞれのキャリッジウェイを選んで1本の線にします。
- 始点は**大まかでOK**。多少ずれていても道路の最寄り地点に補正して作成します（エラーにしません）。
- 外部ライブラリ不要（Python 3.9 以上 + 標準ライブラリのみ）。
- 生成結果はディスクにキャッシュするので、2回目以降は高速です。

---

## 1. すぐに使う

```powershell
py make_line.py 東名高速道路 --start 35.6283,139.6187
```

これだけで、カレントディレクトリの `out/` に次のファイルができます。

| ファイル | 内容 |
| --- | --- |
| `E1-東名高速道路-下り.json` | 下り線のラインデータ（lineData 形式） |
| `E1-東名高速道路-上り.json` | 上り線のラインデータ（lineData 形式） |
| `E1-東名高速道路-下り.meta.json` / `-上り.meta.json` | 始点・終点・延長・補正量・OSM出典などのメタ情報 |

> `python` コマンドが Windows ストアのスタブになっている環境では `py` を使ってください。
> どちらでも動きますが、このREADMEでは `py` で表記します。

### 例

```powershell
# 名神高速道路（小牧IC付近を下り始点として指定）→ 下り・上りの2ファイル
py make_line.py 名神高速道路 --start 35.3031,136.9072 --code E1

# 下り線だけ生成する
py make_line.py 京葉道路 --start 35.7024,139.9006 --direction down

# 上り線だけ生成する
py make_line.py 京葉道路 --start 35.7024,139.9006 --direction up

# 指定地点ではなく、道路の始点から全体を作る
py make_line.py 京葉道路 --start 35.7024,139.9006 --full

# 地図で確認できるプレビューHTMLも同時に出力（下り・上り各1枚）
py make_line.py 東京外環自動車道 --start 35.7615,139.5989 --code C3 --preview

# lineData と GeoJSON と CSV を同時に出力（各方向）
py make_line.py 東名高速道路 --start 35.6283,139.6187 --format lineData,geojson,csv
```

## 2. 始点の指定について（重要）

`--start` に指定するのは **「下り線の始点のおおよその位置」** です。
上り線も同時に生成しますが、**上り線は進行方向が逆**なので、
入力した始点は **上り線の終点** になります。

| 方向 | ラインの始点 | ラインの終点 |
| --- | --- | --- |
| 下り線 | 指定した始点（最寄り地点に補正） | 道路の終点 |
| 上り線 | 道路の終点（＝下り線の終点） | 指定した始点（最寄り地点に補正） |
| `--full` の下り線 | 道路の始点 | 道路の終点 |
| `--full` の上り線 | 道路の終点 | 道路の始点 |

- 指定地点から道路までの最短距離が数km以内なら、道路の最寄り地点に補正します。
  **指定が多少ずれていてもエラーにはなりません。**
- 上り線は下り線の終点から、反対側のキャリッジウェイを通って指定地点までを作ります。
  上下線の位置は数十mずれるのが正常です（別の車線のため）。
- 補正した距離は `meta.json` の `snap_distance_m` と実行結果に出力されます。
- 指定地点が道路から 2km 以上離れている場合は警告を出しますが、生成は続行します。
- 指定地点が道路の**途中**でも生成できます。道路全体の端点のうち、
  東京に近い側を下り始点、遠い側を下り終点と推定し、指定地点から
  下り方向へラインを作ります（10km以上の道路が対象）。
  「浜松付近から名古屋方面へ」のような途中開始に対応するためです。
- 10km未満の短い道路、および `--reverse` 指定時は、従来どおり
  「走行開始点が指定地点に近い方のキャリッジウェイ」を下り線として選びます。
- 東京基準の推定が合わない道路（例: 沖縄自動車道など）では、`--reverse` で
  向きを反転できます。
- 道路の端点（始点・終点）付近を指定した場合、どちらが下り線の始点かは
  形状だけでは自動判定できません。そのため端点付近では確認の警告を表示します。
- OSM上で道路が分断されている場合（未開通区間など）は、そこでラインが
  終わり、「道路データが別区間に分かれています」という警告を表示します。
  新東名高速道路の伊勢原方面〜御殿場間は未開通のため、OSM上でも分断されています。

始点は「緯度,経度」でも「緯度 経度」でも指定できます。
`--lat 35.6283 --lng 139.6187` の形式も使えます。

## 3. 出力形式

### 3.1 lineData（既定）

既存の `app/latlng/*.json` と同じ形式です。1回の実行で
`<ベース名>-下り.json` と `<ベース名>-上り.json` の2ファイルを出力します。

```json
{
    "type": "lineData",
    "version": 1,
    "points": [
        {"lat": 35.628203, "lng": 139.618684},
        {"lat": 35.628561, "lng": 139.615032}
    ]
}
```

- 緯度経度は小数6桁に丸めています。
- 既定では Douglas-Peucker 法で 10m 許容の間引きを行います（`--simplify 0` で無効）。

### 3.2 メタ情報（既定で出力）

```json
{
    "type": "lineDataMeta",
    "version": 1,
    "road": "東名高速道路",
    "road_code": "E1",
    "direction": "down",
    "requested_point_is": "start",
    "start": {"lat": 35.628203, "lng": 139.618684},
    "end": {"lat": 35.30304, "lng": 136.907345},
    "requested_start": {"lat": 35.6283, "lng": 139.6187},
    "snap_distance_m": 10.9,
    "distance_requested_to_start_m": 10.9,
    "distance_requested_to_end_m": 248193.0,
    "length_m": 345623.4,
    "points": 973,
    "trimmed": true,
    "reversed": false,
    "gap_jumps": 1,
    "source": "OpenStreetMap",
    "license": "ODbL-1.0"
}
```

- `direction`: `down`（下り線）または `up`（上り線）
- `requested_point_is`: 入力地点がラインの始点か終点か。下り線は `start`、
  上り線は `end` になります。
- 上り線の `start` は下り線の終点、`end` は入力した始点（の最寄り地点）です。
  上り線では `distance_requested_to_end_m` が「入力地点と上り線終点の距離」になります。
- `trimmed`: 指定地点の最寄り地点から始めたか（`--full` では false）
- `reversed`: `--reverse` で逆向きに生成したか（上下両方が逆向きになります）
- `distance_requested_to_end_m`: 入力地点からライン終点までの直線距離

`--no-meta` で出力を抑制できます。

### 3.3 GeoJSON / CSV

`--format geojson` または `--format csv` を指定すると出力します。
GeoJSON は `[経度, 緯度]` 順の `LineString` です。

### 3.4 プレビューHTML

`--preview` を付けると Leaflet の地図でラインを確認できる HTML を出力します。
下り線・上り線それぞれに1枚ずつ出力されます
（地図タイルの表示にインターネット接続が必要です）。

## 4. オプション

| オプション | 既定値 | 説明 |
| --- | --- | --- |
| `道路名`（位置引数） | – | 道路名。`--road` でも指定可 |
| `--start 緯度,経度` | – | 下り線の始点（おおよそ）。`--lat`/`--lng` でも可 |
| `--code` | 自動 | 道路コード（E1, C3 など）。`road_list.csv` から自動推定もする |
| `--full` | off | 道路の始点から全体を出力 |
| `--reverse` | off | 終点側を指定した場合に、逆方向で作り直す |
| `--direction` | `both` | `both`=下り+上り / `down`=下りだけ / `up`=上りだけ |
| `--out` | – | 出力の**ベースパス**。`-下り` / `-上り` が自動で付きます |
| `--out-dir` | `out` | 出力ディレクトリ |
| `--format` | `lineData` | `lineData,geojson,csv` のカンマ区切り（各方向に出力） |
| `--simplify` | `10` | 間引き許容誤差（m）。0で間引きなし |
| `--gap` | `500` | 道路データの途切れを補う最大距離（m） |
| `--max-expand` | `12` | OSM取得範囲の自動拡張の最大回数 |
| `--connector-max` | `500` | 橋など名称の異なる短い接続ウェイとして使う最大長（m） |
| `--include-links` | off | 立体交差のリンク道路も取得対象にする |
| `--bbox 南,西,北,東` | 自動 | 取得範囲を固定する（自動拡張をスキップ） |
| `--osm-json パス` | – | 保存済みの Overpass 応答（.json / .json.gz）を使う（オフライン用） |
| `--cache-dir` | `.linegen-cache` | OSM 応答のキャッシュ先 |
| `--refresh` | off | キャッシュを使わず再取得 |
| `--mirror URL` | – | Overpass API のミラーを指定（複数可） |
| `--preview [パス]` | – | プレビューHTMLを出力（`パス` はベースパス） |
| `--no-meta` | off | メタ情報JSONを出力しない |
| `--quiet` | off | 進捗表示を抑制 |
| `--version` | – | バージョン表示 |

## 5. 仕組み

```
道路名 + 始点(おおよそ)
        │
        ▼
[1] road_list.csv から道路コードを推定（例: 東名高速道路 → E1）
        │
        ▼
[2] Overpass API で道路ウェイを取得
    ・名前の部分一致 + 道路コードで検索
    ・最初は始点周辺の狭い範囲 → 道路全体が入るまで bbox を自動拡張
    ・「東名高速道路（左ルート）」のような名前のゆれも吸収
    ・橋・トンネルなど名称の異なる短い接続ウェイは ref 一致で補完
    ・取得結果はディスクにキャッシュ
        │
        ▼
[3] 下り線を選ぶ
    ・高速道路は上下線が別々の oneway ウェイ
    ・道路全体の向き（東京に近い端点 → 遠い端点）から下り方向を推定
    ・指定地点が途中でも、そこから下り方向へ連結
        │
        ▼
[4] 下り線を走行方向へ連結
    ・向きの合う次のウェイを選ぶ（分岐では直進を優先）
    ・数百m以内の途切れは方向を確認して接続
    ・指定地点の最寄り地点 → 道路の終点（--full なら道路始点→終点）
        │
        ▼
[5] 上り線を反対側のキャリッジウェイで生成
    ・下り線の終点から上り方向へ連結
    ・指定地点（下り線の始点）に相当する位置で終端を切りそろえる
        │
        ▼
[6] 間引き（Douglas-Peucker 10m）→ 6桁丸め
        │
        ▼
[7] xxxxx-下り.json / xxxxx-上り.json を出力
```

### 取得範囲とパフォーマンス

- 道路が実際に伸びている方向だけ bbox を広げます。
- 広げるときは、**新しく増えた外側の帯（フリンジ）だけ**を Overpass に問い合わせます。
  毎回いちばん外側の広い範囲を取り直さないため、長い道路でもサーバー負荷と取得範囲を抑えられます。
- 道路全体が取得範囲に収まったら停止するので、最終的な取得範囲も道路＋余白程度です。
- 取得結果はキャッシュされます。2回目以降は Overpass に接続せず高速です。
- 範囲を確定できる場合は `--bbox 南,西,北,東` を指定すると1回の取得で済みます（最速）。
- 取得範囲の端に達した疑いがある場合は警告が出ます。`--max-expand` を増やすか `--bbox` を指定してください。

実測例（東名高速道路 東京IC付近始点）:

| 方式 | 最終取得範囲 | 面積 | OSM取得回数 |
| --- | --- | --- | --- |
| 旧方式（全体を再取得） | 33.52,135.68,36.85,140.85 | 約17.2平方度 | 10回以上 |
| 現方式（フリンジのみ） | 34.59,136.52,35.78,139.78 | 約3.9平方度 | 8回 |

生成されるライン（下り346.33km / 上り345.65km）は方式変更前と同一です。

### 動作確認に使ったデータ

| 道路 | 生成延長 | 既存ラインデータとの比較（既存点→生成線） |
| --- | --- | --- |
| 東京外環自動車道 (C3) | 48.19 km | 平均 6.5 m / 95%tile 12.9 m |
| 東名高速道路 (E1) | 345.62 km | 平均 7.8〜8.0 m / 95%tile 17〜18 m |
| 名神高速道路 (E1) | 188.94 km | 平均 6.6〜6.8 m / 95%tile 15 m |
| 京葉道路 (E14) | 34.10 km | 平均 5.5 m / 95%tile 12.1 m |
| 東北自動車道 (E4) | 679.26 km | （比較用の既存データなし） |

既存の `test_app/latlng/*.json` と比べても、平均10m未満・95%tile 20m未満で一致しています。
（京葉道路は延長も 34.10km と一致）
上表は下り線の比較です。上り線も同じ処理で反対側の車線から生成します。
（例: 東京外環 下り 48.19km / 上り 48.12km、京葉道路 下り 34.10km / 上り 34.07km。
京葉道路の上り線は下り線から平均約11.5m横に並走しており、対向車線として妥当です。）
95%tile は集計方法により±1m程度変わります。C3 の最大218mは、比較対象の既存データが
西端で約214m道路とずれていることによるもので、ツールの誤差ではありません
（先頭250mを除くと最大16.7m）。
生成結果は `out/` に出力されます（`out/` は Git 管理外です）。

## 6. うまくいかないとき

### 道路が見つからない

- 道路名の表記を確認してください（例: 「東名」ではなく「東名高速道路」）。
- `--code E1` のように道路コードを明示してください。
- 道路リストは `../data/public/road_list.csv` を使います（無い場合はコード検索なしで動きます）。
- `--bbox 34.6,136.8,35.8,139.8` のように取得範囲を明示できます。

### 途中で線が切れる・短い

- `--gap 1500` のように途切れ補完の距離を広げてください。
- `--code` を指定すると、橋・トンネルなど名称の異なる区間を補いやすくなります。
  長いトンネル（例: 引佐トンネル）も、道路コードが一致すれば接続扱いになります。
- それでも切れる区間は OSM 側で未整備・別名・未開通になっている可能性があります。
  その場合は「道路データが別区間に分かれています」という警告が出ます。
  `--include-links` を試すこともできますが、ランプに迷い込む場合があります。

新東名高速道路の例:

- 伊勢原・海老名側の区間と御殿場〜豊田間は、未開通区間のためOSM上で分断されています。
  伊勢原付近を指定すると約20.6kmで終わり、分断の警告が出ます。
- 御殿場付近を指定すると、豊田まで約206.4km生成できます。
- 浜松付近を指定すると、そこから豊田まで約61.0km生成できます（名古屋方面）。

### Overpass API が混雑している

Overpass API は混雑すると 502 などを返します。このツールは自動でリトライし、
成功した応答を `.linegen-cache/` に保存します。

- 一度取得できた道路は、次回からキャッシュで高速に動きます。
- `--refresh` で再取得できます。
- ネットワークが使えない場合は、Overpass の応答JSONを保存して
  `--osm-json saved.json` で指定してください（テストはこの方式で動いています）。

### 向きがおかしい

- 道路の途中地点を指定した場合、東京に近い端点を下り始点と推定して向きを決めます。
  沖縄自動車道など東京基準が合わない道路では `--reverse` で反転してください。
- 指定地点が下り線の**終点**になっていないか確認してください。
  道路の端点付近では、始点か終点かを形状だけでは判定できないため確認の警告を表示します。
- 終点を指定した場合は `--reverse` を付けると、向きを補正して作り直せます。
- `--full` と組み合わせると、道路全体を始点から作れます。
- 環状道路（山手線のような道路）は始点の概念が曖昧で、OSMの区切りが開始位置になります。

## 7. テスト

```powershell
cd test_line_data
py -m unittest discover -s tests -v
```

- 49 テスト（地理計算・道路名照合・上下線選択・途中地点の方向推定・始点補正・ギャップ補完・分岐・
  bbox自動拡張（フリンジ取得）・長いトンネル名の接続扱い・重複ウェイ統合・CLI・出力形式・メタ情報・向き反転）
- ネットワーク不要。CLI の統合テストは `tests/fixtures/osm_東京外環自動車道.json` を使用します
  （フィクスチャの出典・取得方法は `tests/fixtures/README.md`）。

### 既存ラインデータとの比較

生成したラインと既存の `test_app/latlng/*.json` の距離を比較する補助ツールがあります。

```powershell
py tools/compare_with_existing.py "out/E14-京葉道路-下り.json" "../test_app/latlng/E14-京葉道路.json"

py tools/compare_with_existing.py "out/C3-東京外環自動車道-下り.json" "../test_app/latlng/C3-東京外環自動車道.json"
```

出力例（京葉道路）:

```
既存ライン点 -> 生成ライン点 の最短距離:

生成ライン点 -> 既存ライン点 の最短距離:
  (既存データ全体)   点数=70 平均=5.8m p95=8.1m 最大=17.2m
```

## 9. データの出典・ライセンス

このツールは **OpenStreetMap** のデータを Overpass API 経由で利用します。

- 生成したラインデータは OpenStreetMap に由来する派生物です。
- 利用・公開時は次のクレジット表示が必要です。

> データ: © OpenStreetMap contributors（Open Database License 1.0）
> https://www.openstreetmap.org/copyright

- ODbL 1.0 の条件（表示・継承）に従ってください。
- OSM のデータは日々更新されます。取得範囲や出典はメタ情報に残ります。

## 10. 注意事項

- **OSMに描かれている形**が正解データです。未開通・工事中・未整備区間は含まれません。
- 上下線の区別は OSM の `oneway`（一方通行）の向きに依存します。
  まれにマッピング誤りがあると向きが逆になることがあります。必ずプレビューで確認してください。
- 下り線と上り線は別々の車線から生成するため、同じ場所でも数十mずれます（正常です）。
  2本の線が並走しているかはプレビューHTMLで確認できます。
- 道路の正式な起終点と OSM の描画範囲が一致しない場合があります。
  （例: 京葉道路の篠崎ICより西側は、OSM上は別の道路名・別管理になっていることがあります）
- 生成したラインは地図表示・距離計算用です。法令上の道路中心線ではありません。
- 大量の道路を一括生成する場合は、Overpass API の利用ルールに配慮し、
  キャッシュを有効にしたまま、時間を空けて実行してください。
